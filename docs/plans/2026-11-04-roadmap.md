# Open-source roadmap: six plans and how they fit together

- **Status:** plans only, draft 2 each (2026-11-04). Nothing is built and there are no beads yet.
- **Ask (owner, 2026-11-04):** from the idea-wizard list for open-sourcing Video Agent, plan these: a proper CLI on a
  proper SDK, with local mode and the docs section (#1 + #14); Looks (#2); render engines with Remotion (#3); the GitHub
  Action (#8); redo one scene (#10); screen recording → polished demo (#11).
- **How they were made:** each plan was written against the code, with `path:line` facts checked on 2026-11-04. Each
  then got an independent Fable 5.1 review, which checked its claims against the code and the web. A separate review
  looked only at the seams between the six plans. Every plan folded both reviews into draft 2 and logs what it
  adopted and rejected at its end. (Codex was out of quota until 2026-11-22, so there was no second-model review this
  round.)

## Shared rules all six follow

These came out of the seam review. Each plan's text already follows them.

1. **Feature discovery.** `GET /api/v1/config` has `version` and `features` (snake_case): `remix, narration,
   planning, rest_wait, cli_login, looks, engines, scoped_revision, screen_recording, context, external_ref`. The CLI
   plan adds the array; each feature adds its own string in its own PR. The SDK, CLI, MCP and the Action hide what a
   server doesn't list.
2. **Every route has an `operationId`** (the CLI plan adds them and the uniqueness test). New routes come with one.
3. **No literal prompt-template numbers.** `PROMPT_TEMPLATE_VERSION` goes up by one in each PR that changes the
   template, in merge order. With a feature off, the prompt is byte-identical to today's.
4. **The run manifest stays `v: 1`.** `look`, `engine`, `scope` and `recording` are optional fields, each with its
   own shape check. The render-engines plan sets prepare-run's step order.
5. **One home for frame math:** `src/lib/contract-core.ts`. The first plan with a real second consumer builds it,
   under that name.
6. **`EngineCapabilities`** (render-engines) lists edit ops, `scopedRevision` and `recording`. Redo-a-scene and
   screen recordings are HyperFrames-only in v1.
7. **Packages:** npm workspaces under `packages/` (`sdk`, `cli`, `player`, and a private `action`). The `@video-agent`
   npm scope belongs to someone else, so the packages are `@netlify-labs/video-agent-*`. Never document
   `npx video-agent`.
8. **Words people see:** "scene", "Redo this scene", "Look", "Restyle". Code and the API say `beat`, `scope`, `look`,
   `engine`. CLI flags are `--scene`, `--look`, `--engine`. Screen-recording pointer data is the **pointer trace**
   (`trace.json`). "Telemetry" means only usage or license reporting.
9. **Spike labels** don't collide with `S0`–`S13` in `docs/spikes.md`: CLI `C`, Looks `K`, engines `E`, redo-a-scene
   `B`, screen recording `D`, Action `A`.
10. **The Version DTO grows only by adding fields.** `editable` stays. Webhooks embed the DTO (`src/domain/webhooks.ts:57`),
    so new fields reach `video.ready` for free.

## Build order across plans

**Wave 0, spikes (in parallel):** CLI C1–C4; Looks K1–K4; engines E3–E6 (E1–E2 wait on the Remotion license);
redo-a-scene B1–B3; screen recording D1–D6; Action A1–A5.

**Wave 1, groundwork (in parallel across plans):**
- CLI phase 1: operationIds, `features` + `version`, `/v/{slug}.json` (the oEmbed link the share page advertises
  returns 404 today), oasdiff warning job, `packages/` workspaces.
- Engines phase 1: the Engine interface for HyperFrames only, `versions.engine`, the prepare-run order. No change in
  behaviour.
- Looks phase 1: the `look.json` schema (including `recording`), `look:check --static`, the catalog, `clean`.

**Wave 2:** the SDK (CLI phase 2); Looks phase 2 (data, prompt, API, MCP); redo-a-scene phases 1–2; screen recording
phase 1 (the library role, pointer trace, limits).

**Wave 3:** the remote CLI (CLI phase 3); Action phases 1–2; Looks UI; Remotion authoring (engines phase 2, after
the license); screen recording phase 2 (run scripts, contract); redo-a-scene UI.

**Wave 4:** local mode (CLI phase 4); Action phase 3 (`context`, `external_ref`); later phases of Looks, redo,
screen recording and engines (engines phase 3 needs redo's scope hook).

**Wave 5:** docs nav and pages (CLI phase 6), then the others' docs pages; package release (CLI phase 7, after the
public snapshot in [going public](2026-11-02-going-public.md), since npm provenance needs a public repo); `record` and
`/docs/cli#record`; Remotion sound; the Action's "refresh the demo on release".

**Prompt-template bumps, in merge order:** Looks 2 → redo 2 → engines 1 (only if a byte changes) → screen 2 →
Action 3.

**Migrations, one PR each, regenerating OpenAPI each time:** engines 1 (`versions.engine`) → Looks 2 (`versions.look`,
settings) → redo 2 (`versions.scope`, `versions.beats`) → CLI 3 (`cli_logins`, `cliLoginEnabled`) → screen 1 (media
trace columns, `recordingQuotaBytes`) → engines 2 (`remotion_*`) → Action 3 (`videos.external_ref`).

## Decisions for the owner

Each plan ends with its own numbered questions, each with a recommended default. These six block the most work:

1. **npm scope:** `@netlify-labs/*` (recommended; unclaimed today) or official `@netlify/*`. Blocks the CLI plan's L4
   (create the org, publish placeholders) and every doc example.
2. **Remotion license:** buy Remotion for Automators (or get written confirmation) before any Remotion spike beyond
   E6. The v5.0 terms say setting up the stack ends evaluation, and Netlify is far above the free tier's three-person
   limit. Blocks engines phase 2.
3. **Credit budget for live gates:** the plans' gates add up to several thousand credits (Looks about 3,200; screen
   recording about 1,000; redo about 700; engines and CLI a few hundred each). Recommended: approve each gate when it's
   reached, with `--dry` first and a ceiling.
4. **Local mode:** ship it, even though it spends no Netlify credits (recommended: yes, framed as "make one locally,
   deploy it for your team").
5. **Default look:** None until spike K2 shows `clean` costs about the same as no look (recommended), so API, MCP and
   Action callers don't get a silent prompt change.
6. **Action install:** v1 from this repo's subfolder (`uses: netlify-labs/video-agent/packages/action@<sha>`), with
   the Marketplace listing later (recommended).
