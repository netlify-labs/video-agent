How we built Video Agent

The idea that made it work

A video is just a web page plus time

HyperFrames renders an HTML page with timed scenes into a video, and AI agents are very good at writing HTML. Drag the timeline: each scene is a <section> with a start and a length, and rendering means stepping through the page one frame at a time.

<section data-start="0" data-duration="3">
<h1>Ship in seconds</h1>
</section>
<section data-start="3" data-duration="3">
<pre>$ netlify deploy --prod</pre>
<div class="bar"></div>
</section>
<section data-start="6" data-duration="3">
<h2>Live in seconds</h2>
</section>

When is a video ready?

After rendering, an agent run still writes up its results and Netlify deploys a preview of the run. At first the app waited for all of that. Now it finishes as soon as the render reports its files, which it checks the same way. Switch between the two.

Built entirely on Netlify

One repo, one Netlify project

No video service, no GPU and no extra accounts. Each platform piece does one job.

Agent Runners

Every video is a run: the agent's whole working session on a real Linux machine with Node and FFmpeg, its logs, and a link from the app to the run.

Functions

A Hono API with an OpenAPI spec, background functions for long jobs, and a scheduled sweep every minute that owns every outcome.

Netlify Database

Postgres with Drizzle migrations: videos, versions, run attempts, people, API keys, plans, comments and the queue.

Netlify Blobs

Rendered files, uploads, the media library and preview bundles. A run can upload at about 40 MB/s.

Edge Functions

Signed, expiring file links with byte ranges, public share pages, and a sandboxed live preview of the composition.

AI Gateway

The quick planning questions and the brief, with no model keys to manage.

What we learned the hard way

Lessons from real runs

  • Don't count on the agent's last words

    Agents often didn't end with the JSON list of files we asked for. The render script now posts a signed callback itself; the final answer is only a fallback.

  • An agent may render twice

    One run rendered, lost sight of its output and rendered again, overwriting the uploads, and the app rejected the second file list. Now the newest list wins until the video is ready, and the agent is told not to render twice.

  • Finish when the files arrive

    A run keeps going for minutes after rendering. The app now finishes the video as soon as the render reports its files (see above).

  • Keep the video; add a note

    A narrated video came out 55 seconds instead of 42 and was thrown away. Runs cost real credits, so a video of the wrong length is now kept with a notice.

  • Check everything a run hands back

    A run can write to any Blobs store on the site, so hashes against the authenticated callback and a real MP4 check are what make a video trustworthy.

  • Make it editable by design

    Scenes register through a small seek adapter that stretches their animations, so changing a scene's length needs no code change. That's what makes a browser editor possible on agent-written video.
