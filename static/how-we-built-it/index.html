How we built Video Agent

Type what a video should say and get a branded MP4 a few minutes later. An AI agent writes the video as HTML, renders it with HyperFrames inside a Netlify Agent Runner, and hands it back. Anyone who signs in can use it, and so can scripts and AI tools.

The idea that made it work

A video is just a web page plus time

HyperFrames renders an HTML page with timed scenes into a video, and AI agents are very good at writing HTML. Drag the timeline: each scene is a <section> with a start and a length, and rendering means stepping through the page one frame at a time.

<section data-start="0" data-duration="3">
<h1>Ship in seconds</h1>
</section>
<section data-start="3" data-duration="3">
<pre>$ netlify deploy --prod</pre>
<div class="bar"></div>
</section>
<section data-start="6" data-duration="3">
<h2>Live in seconds</h2>
</section>

The agent writes this, then hyperframes check catches layout and contrast problems before anything renders.

When is a video ready?

After rendering, an agent run still writes up its results and Netlify deploys a preview of the run. At first the app waited for all of that. Now it finishes as soon as the render reports its files, which it checks the same way. Switch between the two.

Built entirely on Netlify

One repo, one Netlify project

No video service, no GPU and no extra accounts. Each platform piece does one job.

Agent Runners

Every video is a run: the agent's whole working session on a real Linux machine with Node and FFmpeg, its logs, and a link from the app to the run.

Functions

A Hono API with an OpenAPI spec, background functions for long jobs, and a scheduled sweep every minute that owns every outcome.

Netlify Database

Postgres with Drizzle migrations: videos, versions, run attempts, people, API keys, plans, comments and the queue.

Netlify Blobs

Rendered files, uploads, the media library and preview bundles. A run can upload at about 40 MB/s.

Edge Functions

Signed, expiring file links with byte ranges, public share pages, and a sandboxed live preview of the composition.

AI Gateway

The quick planning questions and the brief, with no model keys to manage.

Anyone can use it

The quickest way: in Claude, open Settings → Connectors → Add custom connector, paste the MCP URL, then Connect and sign in with Netlify. Now ask Claude for a video, in chat. (If your organization has already added it, just press Connect.)

Web app

Sign in with Netlify. Create, watch, edit, comment, approve and publish.

API

API keys and signed webhooks for scripts and CI.

Other AI tools

Claude Code, Cursor or any MCP client: sign in with Netlify, or use an API key.

Agent skill

Recipes for coding agents, like a pull request into a demo video.

The MCP URL, for the Claude connector or any AI tool. Clients with OAuth only need the URL: sign in with Netlify and approve. Your first sign-in creates your account.

Beyond websites

Agent Runners can run any agentic workflow

Video Agent doesn't build a website. It uses Netlify Agent Runners as a place to do work: a real machine with your repo, your tools and your context, where an agent can write, run, check and hand back a result. Swap the video for anything else and the rest of the app stays the same.

The pattern underneath

1 · Ask

A person, a script, a webhook or an AI tool asks for something through an API or MCP.

2 · Run

An Agent Runner run does the work with real tools: Node, Python, FFmpeg, CLIs, your repo and context.

3 · Hand back

A script uploads the result to Blobs and posts a signed list of what it made.

4 · Check and serve

The app verifies it, then shows, shares and keeps it, with a queue and a sweep around every run.

Some other things the same pattern could do

Release notes, written for you

Read the merged pull requests since the last release, write notes for customers and for the team, and open them for review.

Account briefs before a call

Pull the CRM record, recent calls and product usage, and hand a seller a one-page brief with talking points.

Data reports on a schedule

Run the queries, chart the results, write what changed and why it matters, and publish a page people can open.

Docs that keep up

When an API changes, update the reference and the guides that mention it, run the examples, and propose the change.

Audits on every deploy

Check a preview for accessibility, broken links, performance and copy, and report what to fix with screenshots.

Upgrades across many repos

Apply the same dependency upgrade or migration everywhere, run each repo's tests, and send back what passed.

Decks and one-pagers

Turn a brief into slides or a PDF in the brand, rendered from HTML the same way these videos are.

Localized content

Translate a page, a video's captions or a help article, check the result in context, and hand back every language at once.

Support repros

Rebuild a customer's reported setup in a sandbox, try to reproduce the bug, and attach the steps and logs to the ticket.

The sky's the limit: if an agent can do it on a computer, a run can do it, and an app on Netlify can queue it, check it and put the result in front of people.
