How we built Video Agent

Type what a video should say and get a branded MP4 a few minutes later. An AI agent writes the video as HTML, renders it with HyperFrames inside a Netlify Agent Runner, and hands it back. Anyone who signs in can use it, and so can scripts and AI tools.

The idea that made it work

HyperFrames is an open-source renderer that turns an HTML page with timed animations into a video. That matters because AI agents are very good at writing HTML and CSS. They're much less good at driving video editors.

A Netlify Agent Runner gives an agent a real Linux machine checked out from your repo. Our first test run showed it already had what HyperFrames needs: Node, FFmpeg and FFprobe, and npx hyperframes worked straight away. That run took 45 seconds and cost about 14 credits. A second test showed a run can write files to Netlify Blobs at about 40 MB/s and call back to our API.

Put together: the agent writes video/index.html, checks it, renders it in the runner, uploads the files and tells the app where they are. No video service, no GPU, no extra accounts.

How a video gets made

  1. You describe it

    In the web app, through the API or from an AI tool over MCP. Optionally "Plan it first" asks a few questions and writes a brief you can edit.

  2. It waits its turn

    Requests go into a queue in Netlify Database. A few run at once (three by default), so a busy day can't spend all your credits at the same time.

  3. An agent run writes and checks it

    The app starts an Agent Runner run on the same Netlify project. The agent reads your brand guide, logos and fonts from context/, writes the composition as HTML, and runs hyperframes check until it passes. Music and voice-over are added here when asked for.

  4. One script renders and uploads it

    scripts/render-job.ts renders the MP4, makes the poster, GIF preview and captions, uploads them to Netlify Blobs, and posts a signed list of the files and their SHA-256 hashes back to the app.

  5. The app checks before it trusts

    Finalize compares every uploaded file with those hashes and inspects the MP4 itself before the video becomes "ready". A sweep every minute catches anything that went quiet: lost callbacks, crashed starts, runs that ask a question or run too long.

  6. You watch, edit, revise and share

    Play and download it, change text, timing, colours, media and music in the browser, ask for a revision in plain words, or publish a public share page with an embed snippet.

Built entirely on Netlify

One repo and one Netlify project. Each platform piece does one job:

Agent Runners

Every video is a run: the agent's whole working session, with its logs and a link from the app to the run.

Functions

A Hono API with an OpenAPI spec, background functions for long jobs, and a scheduled sweep every minute that owns every outcome.

Netlify Database

Postgres with Drizzle migrations: videos, versions, run attempts, people, API keys, plans, comments and the queue.

Netlify Blobs

Rendered files, uploads, the media library and the preview bundles. Edge functions serve them with signed, expiring links.

Edge Functions

Fast file delivery with byte ranges, public share pages, and a sandboxed live preview of the composition.

AI Gateway

The quick planning questions and the brief, with no model keys to manage.

Anyone can use it, from anywhere

The same video tasks are available four ways, with the same permissions behind each one:

Web app

Sign in with Netlify. Create, watch progress, edit in the browser, comment, approve and publish.

API

API keys and signed webhooks for scripts and CI, with a reference built into the app.

MCP

Ask Claude, Cursor or any MCP client for a video. Sign in with Netlify through OAuth, or use an API key.

Agent skill

A downloadable skill that teaches coding agents the good path, with recipes like a pull request into a demo video.

Connect your AI tool to the MCP server. Clients that support OAuth only need the URL: you sign in with Netlify and approve the app.

https://netlify-video-agent.netlify.app/mcp

Or, in Claude Code:

claude mcp add --transport http video-agent https://netlify-video-agent.netlify.app/mcp

Install the skill for Claude Code:

curl -fsSL https://netlify-video-agent.netlify.app/skills/netlify-video.zip -o /tmp/netlify-video.zip \
  && unzip -o /tmp/netlify-video.zip -d ~/.claude/skills/

The app's MCP page and Agent skills page have the setup for other tools.

What we learned the hard way

  • Don't count on the agent's last words

    We first asked the agent to end its answer with a JSON list of the files. Agents often didn't. The render script now posts a signed callback itself, and the final answer is only a fallback.

  • An agent may run the render twice

    One run rendered, lost sight of its output, and rendered again, overwriting the uploads. The app rejected the second file list and the video failed. Now the newest list wins until the video is ready, and the agent is told not to render twice.

  • Finish when the files arrive, not when the run ends

    After rendering, a run still writes its results and deploys a preview, which can take minutes. The app now finishes the video as soon as the render reports its files.

  • Keep the video; add a note

    A narrated video came out 55 seconds instead of the 42 asked for, and we threw it away. Runs cost real credits, so a video that's the wrong length is now kept with a notice instead.

  • Check everything a run hands back

    A run can write to any Blobs store on the site, so hashes against the authenticated callback and a real MP4 check are what make a video trustworthy.

  • Make it editable by design

    Scenes register through a small seek adapter that stretches their animations, so changing a scene's length needs no code change. That's what makes a browser editor possible on agent-written video.
